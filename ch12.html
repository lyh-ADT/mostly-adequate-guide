第 12 章：穿越石头

第 12 章：穿越石头

到目前为止，在咱们这出“容器马戏团”（cirque du conteneur）里，你已经见识过我们怎么驯服那头凶猛的函子，把它掰成我们想要的样子，去干任何我们一时兴起想干的勾当。你也已经被晃花了眼：我们借着函数应用，一次抛接好几个危险的效应，再把结果收拢起来。你还坐在那儿目瞪口呆，看着容器被 join 到一起、凭空消失。在“副作用（side effect）”这个小侧棚里，我们见过它们被组合成一个。而就在最近，我们还越过了“自然”的边界，就在你眼皮底下，把一个类型变换成了另一个类型。

接下来是下一个戏法：我们来看看遍历（traversal）。我们会看着各种类型像空中飞人一样在彼此头顶上翻飞，手里还稳稳托着我们的值。我们要像旋转飞车里的小车厢那样，把效应重新排个序。当我们的容器像柔术演员的四肢一样缠成一团时，就可以用这个接口把它们理顺。我们还会看到，顺序不同，效应也不同。快把我的灯笼裤和滑哨拿来，咱们开场。

类型叠类型

咱们来搞点邪门的：

// readFile :: FileName -> Task Error String

// firstWords :: String -> String
const firstWords = compose(intercalate(' '), take(3), split(' '));

// tldr :: FileName -> Task Error String
const tldr = compose(map(firstWords), readFile);

map(tldr, ['file1', 'file2']);
// [Task('hail the monarchy'), Task('smash the patriarchy')]

这里我们读了一堆文件，最后却得到一个毫无用处的 Task 数组。我们该怎么把其中每一个都 fork 出来呢？要是能把类型调换一下，让 Task Error [String] 取代 [Task Error String]，那就再称心不过了。这样一来，我们手里就只有一个装着全部结果的未来值——比起好几个未来值各自慢悠悠地姗姗来迟，这可太合我们异步的胃口了。

再举最后一个棘手的例子：

// getAttribute :: String -> Node -> Maybe String
// $ :: Selector -> IO Node

// getControlNode :: Selector -> IO (Maybe (IO Node))
const getControlNode = compose(map(map($)), map(getAttribute('aria-controls')), $);

你瞧那些 IO，眼巴巴地盼着凑到一块儿。要是能把它们 join 起来，让它俩脸贴着脸跳支舞，那该多美啊——可惜中间杵着一个 Maybe，活像毕业舞会上盯着场的监护人。这儿我们最该做的，是把它们的位置挪一挪，让彼此挨在一起；这样一来，每种类型终于能团圆，我们的签名也就能简化成 IO (Maybe Node) 了。

类型的风水

Traversable 这个接口由两个光辉灿烂的函数组成：sequence 和 traverse。

咱们用 sequence 把类型重新摆一摆：

sequence(List.of, Maybe.of(['the facts'])); // [Just('the facts')]
sequence(Task.of, new Map({ a: Task.of(1), b: Task.of(2) })); // Task(Map({ a: 1, b: 2 }))
sequence(IO.of, Either.of(IO.of('buckle my shoe'))); // IO(Right('buckle my shoe'))
sequence(Either.of, [Either.of('wing')]); // Right(['wing'])
sequence(Task.of, left('wing')); // Task(Left('wing'))

看出发生什么了吗？我们嵌套的类型被整个翻了个面，就像潮湿夏夜里的一条皮裤子。里层的函子（functor）被挪到了外面，外面的被挪到了里面。得说明一句，sequence 对它的参数有那么点儿讲究。它长这样：

// sequence :: (Traversable t, Applicative f) => (a -> f a) -> t (f a) -> f (t a)
const sequence = curry((of, x) => x.sequence(of));

咱们从第二个参数说起。它必须是一个装着应用函子（applicative functor）的 Traversable——听着挺苛刻，可实际上十有八九就是这情形。被翻成 f (t a) 的，正是那个 t (f a)。这签名多有表现力啊！两个类型围着彼此跳方块舞，清楚得跟大白天一样。至于第一个参数，不过是根拐杖，只有在无类型的语言里才用得上。它是一个类型构造器（也就是我们的 of），提供它是为了让我们能翻转 Left 这种死活不肯 map 的类型——这个待会儿再说。

有了 sequence，我们挪动类型就能精准得像街头的三张牌骗子。可它究竟怎么运作呢？咱们来看看某个类型——比如说 Either——会怎么实现它：

class Right extends Either {
  // ...
  sequence(of) {
    return this.$value.map(Either.of);
  }
}

啊对，只要我们的 $value 是个函子（其实必须是应用函子），我们就可以干脆 map 一下构造器，让类型来个蛙跳。

你可能已经注意到，我们把 of 完完全全晾在一边了。它是在 map 派不上用场的时候才被传进来的，比如碰上 Left 这种：

class Left extends Either {
  // ...
  sequence(of) {
    return of(this);
  }
}

我们希望类型最后总是摆成同一个格局，所以像 Left 这种其实没揣着我们内层应用函子的类型，就得有人搭把手，才能做到这一点。应用函子接口要求我们先得有个指向函子（Pointed Functor），这样我们手里总有个 of 可以传进去。而在有类型系统的语言里，外层类型从签名就能推断出来，不必显式给出。

效应大杂烩

就容器而言，顺序不同，结果就不同。如果我手里是 [Maybe a]，那是一堆可能的值；而如果我手里是 Maybe [a]，那是一个可能的一堆值。前者表示我们会宽宏大量，把“好的那些”留下来；后者则意味着这是“全有或全无”的局面。同样，Either Error (Task Error a) 可以表示客户端的校验，而 Task Error (Either Error a) 可以表示服务端的校验。类型一换，效应就换。

// fromPredicate :: (a -> Bool) -> a -> Either e a

// partition :: (a -> Bool) -> [a] -> [Either e a]
const partition = f => map(fromPredicate(f));

// validate :: (a -> Bool) -> [a] -> Either e [a]
const validate = f => traverse(Either.of, fromPredicate(f));

这里有两个不同的函数，区别只在于我们用 map 还是 traverse。第一个，partition，会按照谓词函数给我们一个由 Left 和 Right 组成的数组。这很有用：宝贵的数据能留下来以备后用，而不是跟洗澡水一起被倒掉。validate 则会把第一个没过谓词的项装在 Left 里给我们；要是万事大吉，就把所有项都装在 Right 里。选一个不同的类型顺序，行为就不同。

咱们来看看 List 的 traverse 函数，搞清楚 validate 这套手法是怎么搭起来的。 

traverse(of, fn) {
    return this.$value.reduce(
      (f, a) => fn(a).map(b => bs => bs.concat(b)).ap(f),
      of(new List([])),
    );
  }

这不过是在列表上跑一次 reduce。那个 reduce 函数是 (f, a) => fn(a).map(b => bs => bs.concat(b)).ap(f)，看着有点唬人，咱们一步步拆开看。

  1. reduce(..., ...)

    记住 reduce :: [a] -> (f -> a -> f) -> f -> f 这个签名。第一个参数其实由 $value 上的点号语法提供了，所以它是一个装东西的列表。 然后我们需要一个函数，接收一个 f（累加器）和一个 a（被迭代的那一项），返回给我们一个新的累加器。

  2. of(new List([]))

    种子值是 of(new List([]))，在我们的例子里就是 Right([]) :: Either e [a]。注意，Either e [a] 同时也会是我们最终的结果类型！

  3. fn :: Applicative f => a -> f a

    把它套到上面的例子里，fn 其实就是 fromPredicate(f) :: a -> Either e a。

    fn(a) :: Either e a

  4. .map(b => bs => bs.concat(b))

    当它是 Right 时，Either.map 会把右边的值传给函数，然后用结果返回一个新的 Right。在这个例子里，函数只有一个参数（b），返回的是另一个函数（bs => bs.concat(b)，其中 b 因为闭包而在作用域内）。当它是 Left 时，返回的就是左边的值。

    fn(a).map(b => bs => bs.concat(b)) :: Either e ([a] -> [a])

  5. .ap(f)

    记住这里的 f 是个应用函子，所以我们能把函数 bs => bs.concat(b) 应用到 f 里那个 bs :: [a] 值上。幸运的是，f 来自我们最初的种子，类型如下：f :: Either e [a]——顺带说一句，当我们应用 bs => bs.concat(b) 时，这个类型也保持不变。 当 f 是 Right 时，这会调用 bs => bs.concat(b)，返回一个把该项加进列表的 Right。当 f 是 Left 时，返回的就是那个左值（分别来自上一步或上一轮迭代）。

    fn(a).map(b => bs => bs.concat(b)).ap(f) :: Either e [a]

这看似神奇的变换，在 List.traverse 里只用区区 6 行代码就实现了，而且全靠 of、map 和 ap，所以对任何应用函子都管用。这是个绝好的例子， 说明那些抽象只需极少的假设（顺便说一句，这些假设可以在类型层面上声明并检查！），就能帮我们写出高度通用的代码。

类型圆舞曲

该回头收拾收拾我们开头那些例子了。

// readFile :: FileName -> Task Error String

// firstWords :: String -> String
const firstWords = compose(intercalate(' '), take(3), split(' '));

// tldr :: FileName -> Task Error String
const tldr = compose(map(firstWords), readFile);

traverse(Task.of, tldr, ['file1', 'file2']);
// Task(['hail the monarchy', 'smash the patriarchy']);

用 traverse 代替 map，我们成功地把那些撒野的 Task 像赶羊一样赶进了一个整整齐齐的结果数组。如果你熟悉的话，这就像 Promise.all()——只不过它不是什么一次性的自定义函数，不是的，它对任何 Traversable 类型都管用。这些数学味儿的 API 往往能用一种可互操作、可复用的方式，把大部分我们想干的事收拢进来，而不必让每个库都为单一类型把同样的函数重新发明一遍。

咱们把最后一个例子也收拾干净，好有个了结（说的不是闭包那个 closure，别多想）：

// getAttribute :: String -> Node -> Maybe String
// $ :: Selector -> IO Node

// getControlNode :: Selector -> IO (Maybe Node)
const getControlNode = compose(chain(traverse(IO.of, $)), map(getAttribute('aria-controls')), $);

我们把 map(map($)) 换成了 chain(traverse(IO.of, $))：它一边 map，一边通过 chain 把两个 IO 拍平，顺手就把我们的类型翻了个个儿。

无法无天

好了好了，在你开始横挑鼻子竖挑眼、把退格键当法槌猛敲、想从这一章全身而退之前，先花点工夫认清：这些定律是有用的代码保证。容我大胆断言，大多数程序架构的目标，就是想给代码加上有用的限制、把可能性收窄，好把身为设计者和读者的我们引向答案。

没有定律的接口，不过是绕弯子罢了。跟任何别的数学结构一样，为了我们自己脑子清醒，必须把它的性质亮出来。这跟封装的效果差不多：它保护了数据，还让我们能把这个接口换成另一个遵纪守法的良民。

跟上吧，我们还有几条定律要摸清楚。

恒等

const identity1 = compose(sequence(Identity.of), map(Identity.of));
const identity2 = Identity.of;

// 用 Right 试一下
identity1(Either.of('stuff'));
// Identity(Right('stuff'))

identity2(Either.of('stuff'));
// Identity(Right('stuff'))

这个应该不难。如果我们往函子里放一个 Identity，再用 sequence 把它翻到外面来，那跟一开始就直接把它搁在外面是一回事。我们挑 Right 当小白鼠，因为它便于试这条定律，也便于查看。那里放个任意函子，本来很正常，不过定律本身用上了具体的函子，也就是 Identity，这可能会让人挑挑眉毛。别忘了，一个范畴是由其对象之间的态射（morphism）定义的，而这些态射具有满足结合律的组合和恒等。当我们跟函子范畴打交道时，自然变换（natural transformation）就是那些态射，而 Identity 呢，就是恒等。在演示定律这件事上，Identity 函子跟我们的 compose 函数一样基础。事实上，我们干脆也别再硬撑了，照着Compose 类型的路子也来一套：

组合

const comp1 = compose(sequence(Compose.of), map(Compose.of));
const comp2 = (Fof, Gof) => compose(Compose.of, map(sequence(Gof)), sequence(Fof));


// 拿我们手边现成的几个类型试一试
comp1(Identity(Right([true])));
// Compose(Right([Identity(true)]))

comp2(Either.of, Array)(Identity(Right([true])));
// Compose(Right([Identity(true)]))

这条定律如你所料地保住了组合：如果我们交换函子的组合方式，不该看到任何意外，因为组合本身就是一个函子。我们随随便便挑了 true、Right、Identity 和 Array 来试它。像 quickcheck 或 jsverify 这样的库，可以帮我们对输入做模糊测试，从而验证这条定律。

作为上述定律的一个自然后果，我们获得了融合遍历的能力——从性能角度看，这可相当划算。

自然性

const natLaw1 = (of, nt) => compose(nt, sequence(of));
const natLaw2 = (of, nt) => compose(sequence(of), map(nt));

// 随便找个自然变换，用我们友好的 Identity/Right 函子试一下。

// maybeToEither :: Maybe a -> Either () a
const maybeToEither = x => (x.$value ? new Right(x.$value) : new Left());

natLaw1(Maybe.of, maybeToEither)(Identity.of(Maybe.of('barlow one')));
// Right(Identity('barlow one'))

natLaw2(Either.of, maybeToEither)(Identity.of(Maybe.of('barlow one')));
// Right(Identity('barlow one'))

这跟我们的恒等律差不多。如果我们先让类型翻个身，再在外面跑一个自然变换，那应该等于先 map 一个自然变换，然后把类型翻过来。

这条定律的一个自然后果是：

traverse(A.of, A.of) === A.of;

这同样，从性能角度看是件好事。

总结

Traversable 是个强大的接口，它让我们能像一位会隔空移物的室内设计师那样，轻轻松松地把类型重新布置一番。换个顺序，我们就能得到不同的效应，还能把那些害得我们没法用 join 把它们熨下去的讨厌类型褶皱一并抹平。接下来，我们要绕一小段路，去看看函数式编程（functional programming）里——也许甚至算代数本身里——最强大的接口之一：第 13 章：幺半群把一切聚拢

      default:
        return String(t);
    }
  }

  function inspectArgs(args) {
    return Array.isArray(args) ? `[${args.map(inspect).join(', ')}]` : inspectTerm(args);
  }

  return (typeof x === 'function') ? inspectFn(x) : inspectArgs(x);
}

// NOTE 一个稍微加强版的 `curry`，它还会记录一个函数到底是被部分应用了，
// 还是一次性传齐了所有参数。
// 这有助于在验证练习时给出更有用的提示。
function curry(fn) {
  assert(
    typeof fn === 'function',
    typeMismatch('function -> ?', [getType(fn), '?'].join(' -> '), 'curry'),
  );

  const arity = fn.length;

  return namedAs(fn.name, function $curry(...args) {
    $curry.partially = this && this.partially;

    if (args.length < arity) {
      return namedAs(fn.name, $curry.bind({ partially: true }, ...args));
    }

    return fn.call(this || { partially: false }, ...args);
  });
}


// NOTE 一个稍微加强版的 `compose`，它还会记录被调用函数的链条。
// 最终，用 `compose` 创建出来的函数会带一个 `callees` 变量，
// 里面是所有被调用函数的名字。
// 这有助于在验证练习时给出更有用的提示。
function compose(...fns) {
  const n = fns.length;

  return function $compose(...args) {
    $compose.callees = [];

    let $args = args;

    for (let i = n - 1; i >= 0; i -= 1) {
      const fn = fns[i];

      assert(
        typeof fn === 'function',
        `Invalid Composition: ${ordinal(n - i)} element in a composition isn't a function`,
      );

      $compose.callees.push(fn.name);
      $args = [fn.call(null, ...$args)];
    }

    return $args[0];
  };
}

class Map {
  constructor(x) {
    assert(
      typeof x === 'object' && x !== null,
      'tried to create `Map` with non object-like',
    );

    this.$value = x;
  }

  inspect() {
    return `Map(${inspect(this.$value)})`;
  }

  getType() {
    const sample = this.$value[Object.keys(this.$value)[0]];

    return `(Map String ${sample ? getType(sample) : '?'})`;
  }

  insert(k, v) {
    const singleton = {};
    singleton[k] = v;
    return new Map(Object.assign({}, this.$value, singleton));
  }

  reduce(fn, zero) {
    return this.reduceWithKeys((acc, _, k) => fn(acc, k), zero);
  }

  reduceWithKeys(fn, zero) {
    return Object.keys(this.$value)
      .reduce((acc, k) => fn(acc, this.$value[k], k), zero);
  }

  map(fn) {
    return new Map(this.reduceWithKeys((obj, v, k) => {
      obj[k] = fn(v); // eslint-disable-line no-param-reassign
      return obj;
    }, {}));
  }

  sequence(of) {
    return this.traverse(of, x => x);
  }

  traverse(of, fn) {
    return this.reduceWithKeys(
      (f, a, k) => fn(a).map(b => m => m.insert(k, b)).ap(f),
      of(new Map({})),
    );
  }
}

class Maybe {
  static of(x) {
    return new Maybe(x);
  }

  get isNothing() {
    return this.$value === null || this.$value === undefined;
  }

  get isJust() {
    return !this.isNothing;
  }

  constructor(x) {
    this.$value = x;
  }

  ap(f) {
    return this.isNothing ? this : f.map(this.$value);
  }

  chain(fn) {
    return this.map(fn).join();
  }

  inspect() {
    return this.isNothing ? 'Nothing' : `Just(${inspect(this.$value)})`;
  }

  getType() {
    return `(Maybe ${this.isJust ? getType(this.$value) : '?'})`;
  }

  join() {
    return this.isNothing ? this : this.$value;
  }

  map(fn) {
    return this.isNothing ? this : Maybe.of(fn(this.$value));
  }

  sequence(of) {
    return this.traverse(of, x => x);
  }

  traverse(of, fn) {
    return this.isNothing ? of(this) : fn(this.$value).map(Maybe.of);
  }
}


class Task {
  constructor(fork) {
    assert(
      typeof fork === 'function',
      'invalid `fork` operation given to Task constructor. Use `Task.of` if you want to lift a value in a default minimal Task context.',
    );

    this.fork = fork;
  }

  static of(x) {
    return new Task((_, resolve) => resolve(x));
  }

  static rejected(x) {
    return new Task((reject, _) => reject(x));
  }

  ap(f) {
    return this.chain(fn => f.map(fn));
  }

  chain(fn) {
    return new Task((reject, resolve) => this.fork(reject, x => fn(x).fork(reject, resolve)));
  }

  inspect() { // eslint-disable-line class-methods-use-this
    return 'Task(?)';
  }

  getType() { // eslint-disable-line class-methods-use-this
    return '(Task ? ?)';
  }

  join() {
    return this.chain(x => x);
  }

  map(fn) {
    return new Task((reject, resolve) => this.fork(reject, compose(resolve, fn)));
  }
}

// NOTE 一个稍微加强版的 `curry`，它还会记录一个函数到底是被部分应用了，
// 还是一次性传齐了所有参数。
// 这有助于在验证练习时给出更有用的提示。
function curry(fn) {
  assert(
    typeof fn === 'function',
    typeMismatch('function -> ?', [getType(fn), '?'].join(' -> '), 'curry'),
  );

  const arity = fn.length;

  return namedAs(fn.name, function $curry(...args) {
    $curry.partially = this && this.partially;

    if (args.length < arity) {
      return namedAs(fn.name, $curry.bind({ partially: true }, ...args));
    }

    return fn.call(this || { partially: false }, ...args);
  });
}


// NOTE 一个稍微加强版的 `compose`，它还会记录被调用函数的链条。
// 最终，用 `compose` 创建出来的函数会带一个 `callees` 变量，
// 里面是所有被调用函数的名字。
// 这有助于在验证练习时给出更有用的提示。
function compose(...fns) {
  const n = fns.length;

  return function $compose(...args) {
    $compose.callees = [];

    let $args = args;

    for (let i = n - 1; i >= 0; i -= 1) {
      const fn = fns[i];

      assert(
        typeof fn === 'function',
        `Invalid Composition: ${ordinal(n - i)} element in a composition isn't a function`,
      );

      $compose.callees.push(fn.name);
      $args = [fn.call(null, ...$args)];
    }

    return $args[0];
  };
}

// 还是一次性传齐了所有参数。
// 这有助于在验证练习时给出更有用的提示。
function curry(fn) {
  assert(
    typeof fn === 'function',
    typeMismatch('function -> ?', [getType(fn), '?'].join(' -> '), 'curry'),
  );

  const arity = fn.length;

  return namedAs(fn.name, function $curry(...args) {
    $curry.partially = this && this.partially;

    if (args.length < arity) {
      return namedAs(fn.name, $curry.bind({ partially: true }, ...args));
    }

    return fn.call(this || { partially: false }, ...args);
  });
}


// NOTE 一个稍微加强版的 `compose`，它还会记录被调用函数的链条。
// 最终，用 `compose` 创建出来的函数会带一个 `callees` 变量，
// 里面是所有被调用函数的名字。
// 这有助于在验证练习时给出更有用的提示。
function compose(...fns) {
  const n = fns.length;

  return function $compose(...args) {
    $compose.callees = [];

    let $args = args;

    for (let i = n - 1; i >= 0; i -= 1) {
      const fn = fns[i];

      assert(
        typeof fn === 'function',
        `Invalid Composition: ${ordinal(n - i)} element in a composition isn't a function`,
      );

      $compose.callees.push(fn.name);
      $args = [fn.call(null, ...$args)];
    }

    return $args[0];
  };
}

const keepHighest = function keepHighest(x, y) {
  try {
    keepHighest.calledBy = keepHighest.caller;
  } catch (err) {
    // NOTE node.js 运行在严格模式下，禁止使用 '.caller'
    // 这里有个丑陋的 hack，从堆栈跟踪里把调用者捞出来。
    const [, caller] = /at (\S+)/.exec(err.stack.split('\n')[2]);

    keepHighest.calledBy = namedAs(caller, () => {});
  }

  return x >= y ? x : y;
};
